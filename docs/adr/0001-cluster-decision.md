# ADR-0001：四簇立场分类「修补规则 or 升级 LLM 判定」的决策记录

状态：已接受（US-16，Sprint 1）
日期：2026-08-28（计划 9/13 真实数据接入后复核）

## 背景与问题

知辩的四簇立场分类（支持/反对/条件成立/证据不足）当前由确定性规则实现（`src/cluster.js` 词表 + 否定前缀处理）。规则分类在「无显性关键词、转折、让步、反问、双面论证」的真实知乎表达上命中率低（Gold Set 基线约 6.7%，见 `data/eval-baseline.json`）。因此必须在真实数据接入前，把「何时修补规则、何时升级 LLM 判定」的决策标准固定下来，避免两个陷阱：一是在小样本上反复调权自欺；二是用 LLM 黑盒覆盖全部判断却失去可追溯性。

## 决策

1. 主链路保持「确定性规则 + 来源可追溯」不变（这是产品对可追溯性的承诺，Sprint 0 已固化）。
2. 规则的表现用 Gold Set（人工标注回归集）持续度量，基线注册表记录趋势（`scripts/compare-eval.mjs`），命中率较上次下降超过阈值（默认 5pt）阻止提交（US-18）。
3. 「修补规则 or 升级 LLM 判定」的唯一决策输入是：**真实采样集（`--real`）的分歧率**，而不是 Gold Set 命中率。分歧率高 → 规则在真实表达上失效，升级 LLM 判定（直答 Agent 的立场归因）；分歧率低 → 规则可用，按差异案例修补词表。
4. 升级 LLM 判定的边界：LLM 只做「立场归因」，不做「事实主张」；来源引用必须保留，不允许 LLM 凭空生成来源（这是产品红线，Sprint 0 的 source-gated 契约）。

## 决策依据（对比过的选项）

- 方案 A（立即重写为 LLM 判定）：丢弃确定性，命中率可能更高，但失去可追溯性、离线可用性，且演示数据下无法验证。拒绝。
- 方案 B（立即扩充词表到高命中率）：在 30 例小集上调词表，等于反向构造，会过拟合 Gold Set。拒绝。
- 方案 C（本方案）：保持规则主链路，Gold Set + 真实采样双轨度量，把升级决策推迟到真实数据接入后、以分歧率而非小样本命中率为准。接受。

## 决策后果

正面：分类表现可度量、可审计；升级决策有真实数据依据；不冒进改架构。
负面：在拿到真实数据前，规则命中率仍低（诚实呈现为「证据不足」簇偏多），这是规则分类的已知局限，产品以「证据不足」兜底而非猜测。

## 待验证项（9/13 真实数据接入后）

- 运行 `scripts/sample-real.js` 采样真实检索内容 → 人工补标 → `_smoke_regression.mjs --real=` 报告分歧率。
- 分歧率 > 阈值（建议 30%）：启动 LLM 立场归因升级；否则：按差异案例修补词表并重跑不变量测试（`cluster-invariant.test.mjs`）。
- 本 ADR 在真实数据结论出来后需复核更新。
